# ReCo 数据集阶段调研结论

## 调研范围与状态

- 官方 README 已明确说明：展示样例是每个任务随机抽 50 条，**没有人工挑选或 cherry-picking**。因此官方展示可以用于粗看总体质量，不应再写成“选择机制未知”。
- 本地校验后的 `examples.tar` 实际有 204 条，`add`、`remove`、`replace`、`style` 各 51 条；比 README 所述每类 50 条多出的 1 条来源未解释，报告保留这个实测差异。
- 首批审核表按每类自然排序后的前 10 条生成，共 40 条。它是官方随机展示池上的确定性子集，不是我们重新对 ReCo-Data 全量做的随机抽样。
- 已实际浏览 `add`、`remove`、`replace` 各 10 条，共 30 条。
- `style` 属于全局风格转换，与当前的人脸、头发、服装、首饰/配饰和表情编辑目标关系较弱，因此本轮主动跳过，不把默认值视为人工审核结果。
- 本报告只反映官方小规模可视化示例，不代表 ReCo-Data 全量数据的精确分布或通过率。

## 审核记录的解释限制

官方示例视频为左右拼接格式：左侧是 source，右侧是 target。复核代表帧时发现，当前部分备注使用了相反方向，例如 `add/0c036`、`replace/4e5a0` 和 `replace/4d5a2`。因此：

- 现有备注仍可用于发现形变、交互异常和非编辑区域变化；
- 当前 `instruction_correctness` 等数值不宜直接汇总成质量通过率；
- 两条 `add` 记录还使用了规范外的 `x`，应视为“未判定”，而不是通过或失败；
- 若未来决定正式使用 ReCo，再只对筛出的人物属性候选按正确方向复核，无需返工审核全部官方示例。

## 分任务观察

| 任务 | 与当前目标的关系 | 阶段观察 |
| --- | --- | --- |
| `replace` | 四类中最高 | 包含人物、服装以及人物与机器人/动物间的替换，最接近人物属性编辑；但示例中仍有手部动作不一致、背景变化、局部模糊和替换结果生硬等问题。 |
| `add` | 中低 | 多数是增加人物、动物或物体，而不是修改已有人的细粒度属性；可作为局部编辑补充，但不是当前核心数据。 |
| `remove` | 低 | 多数是删除人物或物体，不直接覆盖身份、发型、服装和配饰修改；人物被删除后仍保留影子、动作或物体交互是明显问题。 |
| `style` | 暂不使用 | 属于全局风格转换，本轮未审核，后续除非任务范围扩展，否则不投入时间。 |

## 常见问题

1. 编辑后的物理和交互逻辑不完整，例如人物消失后影子、叉子或其他交互物仍继续运动。
2. 非编辑区域不能完全保持，包括背景、灯光、物体材质和人物动作发生变化。
3. 手部、衣服边缘和人物替换区域容易出现模糊、粘连、形变或不自然质感。
4. 部分 source 本身较人工或内容不自然，会降低其对真实人物域适配的价值。
5. 当前样本量和记录一致性不足以支持对全量数据可用比例作可靠估计。

## 阶段结论

ReCo 更适合作为通用局部视频编辑配对数据的候选补充，不适合作为真实人物域数据的主体。当前不建议下载 500K+ 全量数据，也不进入训练格式转换。

如果以后重新考虑 ReCo，优先下载 metadata，先按 `replace` 任务和人物属性关键词筛选身份/人脸、发型/发色、服装、首饰/配饰和表情候选，再拉取覆盖这些候选的最少视频 shard 并复核质量。
