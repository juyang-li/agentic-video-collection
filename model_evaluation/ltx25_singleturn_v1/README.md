## 推理步骤

1. 固定官方 LTX-2.5 模型、代码 revision、所有 IC-LoRA 文件/权重/强度和工作流 JSON。优先官方 BF16 distilled 单阶段作为快速可用起点，结果注明“基模 + 官方 adapter”，不称裸基模。后续 SFT 使用的非蒸馏训练权重若不同，须复测训练起点，不能直接拿 distilled 结果作训练前基线。
2. 先跑 4 条代表样本：`cloth_004`、`cloth_010`、`appearance_017`、`camera_005`，计入正式 60 条，记录启动/编码/采样/解码耗时及峰值显存。确认完整 source 视频进入条件，独立服装图进入参考条件。不能用 source 第一帧 + 服装图生成冒充 source 视频编辑。
3. **参考协议尚待跑通**：Ingredients 官方主工作流是参考图拼板生成，并未凭文档确认通用 source 视频 + 服装图换衣。generic V2V 工作流接视频但通常搭配任务专用 adapter，不能随意把 Instant Shave 当通用编辑。先检查官方组合，跑通后固定；不支持则将任务记为 unsupported，保留 bench 输入，不以失败视频判模型能力弱，不悄悄降级协议。需要多个 adapter 的任务分组单报，并记录后续微调起点。
4. 派生规格提案：原速前 97 帧 @24 fps（约 4 秒）；横屏 768×432 等比例装入 768×448、竖屏 432×768 等比例装入 448×768，使用 padding，避免裁掉头或腿。两边均符合 32 倍数；最终服从选定官方工作流尺寸要求。source 与 GT 使用相同时间窗口和变换；短片不循环或减速，取不超时长的合法 `8k+1` 帧数并记录。原始媒体保持原样。首测若 padding 或分辨率不适合官方训练分布，统一调整后重新冻结配置。
5. 单 seed=42，batch=1，无超分，无逐样本参数调优。提示增强默认关闭；若官方推荐必须开启，缓存最终提示并验证不改变目标或暴露 GT。采样步数、guidance、IC 强度沿用选定官方工作流值，测速后冻结。
6. 优先一张 H200 一个常驻推理进程，4 个均衡分片各 15 条；能单卡装下才按此并发。不能则 2 卡/实例 ×2 并重新估算。按 adapter 分组加载以减少切换；文本编码缓存/模型 staging 放作业本地临时盘，正式输出和元数据回传 scratch。显存与实际吞吐尚未测量。
7. 可选 4 次“只替换服装参考图”的配对对照：固定 source、提示、seed、adapter，换用同类另一张衣服图，比较输出衣服是否跟随变化，防止只看文字或无视 ref。不要求不同衣服输出保持相同。它们是诊断输出，不并入正式 60 条成功率。
8. 生成可续跑记录：sample_id、model/code/adapter hashes、最终提示、预处理参数、seed、耗时、显存、输出路径、异常；失败和 unsupported 单列。产出后做本地解码和配对检查，制作连续下拉、无评分栏的结果审核页，放 source/ref/output/可选 GT。按既有路径打包到百度网盘，不做整包回读。

## 时间预算与判断

目标 4 张 H200 推理 1–2 小时，**未测速，不能承诺**。4 个常驻进程、64 次输出约 16 波；给加载与预处理预留 20 分钟，则单条应约在 150–375 秒内。首次下载、依赖安装和排队不计入稳态推理耗时，也另行报告。前 4 条确认后，以 `加载/预处理 + ceil(剩余样本数/并发数) × 实测 p90 单条耗时` 估算，并计入剩余 adapter 切换开销。超预算时先去掉 4 个诊断输出，再统一缩短片长/规格并重新记录；不按已生成质量挑选保留样本。

分开查看参考服装匹配、指令完成、人物/背景/原动作保持、时间稳定和画质。25 条换衣可参考 GT；其它任务以 source、指令和输出检查，不伪造 GT。镜头任务不把镜头应有变化算保持失败。

基模存在可学习空间的证据是：能读取条件、能稳定生成并保住大部分原内容，但衣服细节/局部编辑有系统性缺口。无条件读取能力与任务未支持应先解决工程/接口问题；单凭失败率高不能认定 SFT 无效。表现好也不能断言没有增益，应看细节、困难组与一致性。60 条用于筛选起点，不能证明微调数据有效；最终仍需相同起点、相同冻结 bench 的训练前后对比。
