# LTX-2.5 / A849 / VACE：百样本阶段总结

## 四卡吞吐量估算

实测设备为 **4×H200**（目录名 a100 指100个样本，不指 A100 GPU）。每卡一个独立推理进程，四份样本并行；不是四卡协同生成同一条。协议：49帧、12fps、40步、seed42，1280×736或736×1280。以下以每模型100条正式输出为依据，不能直接套用到A100、其他帧数或分辨率。

| 模型 | 单条中位耗时 | 四卡估算吞吐量 | 100条纯生成时间 |
| --- | ---: | ---: | ---: |
| LTX-2.5 基座 | 160.89秒 | 约90条/小时 | 约1.11小时 |
| 师兄 A849 LoRA | 161.35秒 | 约89条/小时 | 约1.12小时 |
| Wan2.1-VACE-14B | 933.65秒 | 约15条/小时 | 约6.66小时 |

吞吐量公式为 `4×3600 / 单条中位秒数`；100条时间使用实测累计GPU小时除4（4.44、4.46、26.63），是假设负载均衡的估算。三个模型各100条合计约8.88小时纯生成；不含排队、模型加载、输入编码、分割/跟踪/pose、重试和打包上传。固定分片的长尾会增加墙钟时间，不应把估算当作端到端承诺。LTX耗时包含视频解码；VACE记录pipeline生成时间。加载计时典型值基座25秒、A849153秒、VACE140秒，应每进程加载一次并持续处理多条，勿逐条重启。

证据：`metadata/final_inference_summary.json`、`outputs/<model>/*.json`、`logs/`。这是当前协议的测量及四卡外推，没有新增基准作业。

## 最重要的经验

- 固定抽样和输入协议，GT与target caption仅用于评测。完整保留CoinVE有序复合指令；TripVVT完整编辑prompt与官方caption分开展示。效果弱但协议合法的结果照实保留，不按输出效果换样。
- 先少量首测检查实际输入和完整视频，再扩到全量。可解码或像素差异大均不代表完成编辑；参考替换诊断独立于正式100条。
- VACE重绘的可编辑RGB区域必须先填128，再送官方pipeline；仅传原RGB和mask会产生错误约束。mask白色表示可编辑，黑色表示保持。局部mask从SOURCE产生，不读GT。
- 人体分区与SAM2联合更适合身份/服装编辑；发型解析用头部ROI，浅色头发、马尾、多人物遮挡需保留局限记录。动作按官方pose协议准备，限制ORT线程避免CPU过量竞争。
- LTX复用原生参考顺序、文本/参考缓存和解码器；不要修改师兄训练环境或历史缓存。VACE使用隔离环境，固定模型revision和依赖版本。
- 后续审核页保持无评分连续滚动，固定任务导航可直接跳转；VACE prepared input和overlay只在整个包前两个样本展示，pose及正式输出照常显示。新规则用于后续构建，已上传历史包不重传。
- 已上传内容以工具返回complete为依据，仅传ZIP，不额外核对远端哈希、大小或整包回读。清理后依靠网盘恢复历史媒体，不能只看旧complete JSON就认为视频仍在本地。
