# 视频编辑测评经验：GT三指标与VBench

更新：2026-11-21。本文记录本项目已经执行过的协议、速度和问题；任意数据集的安装与命令分别见[GT三指标指南](SSIM_PSNR_LPIPS_README.md)和[VBench指南](VBENCH_README.md)。最终实验数值见[300／116汇总](FINAL_RESULTS_300_116.md)。

## 1. 指标回答什么问题

| 指标 | 比较对象／含义 | 不能替代什么 |
|---|---|---|
| SSIM ↑、PSNR ↑、LPIPS ↓ | 输出与对应GT的逐帧保真度 | 指令完成、参考身份匹配、合理多解的人工判断 |
| Subject／Background Consistency ↑ | 输出内部主体／背景一致性 | 参考匹配、编辑正确性；冻结视频也可能高分 |
| Aesthetic／Imaging Quality ↑ | 美学／成像质量 | 指令正确性；尺寸与编码也影响分数 |
| Temporal Flickering ↑ | 全量原始邻帧像素变化分数 | 纯闪烁结论，正常动作和镜头运动也影响分数 |
| Motion Smoothness ↑ | 输出运动平滑度 | 动作正确性或运动充分性 |

GT三指标只与GT比较，不与SOURCE比较。VBench只评输出，不使用GT作为条件。VLM的IF／CP另外报告，不能混成一个“编辑总分”；六项VBench简单平均也不是官方Total Score。

## 2. 先冻结身份、时间和画面

固定 `(数据集, 样本ID, 模型)`、UID、完整指令、有序参考、输入／输出／GT哈希、模型权重、采样协议和软件版本。相同ID不一定是同一视频；300集和V4自建116集不能拼接排名。缓存复用同时核对媒体与协议身份，不能只检查文件名或存在性。

- 先冻结时间轴，再按实际PTS选最近帧，平局取后帧；不搜索最佳偏移、不插帧、不变速、不补生成尾帧。
- 本批UE为12fps、含端点121帧；真实视频为49–97帧。121帧不是所有“10秒视频”的通用定义。
- H3原生24fps按真实生成帧0、2、…投影到冻结12fps时间点，多余原生尾帧排除；完整原生流仍需解码验证。
- GT合法末端量化例外只适用于预先记录的GT端点，不能用于补长模型输出。
- GT指标按已知contain几何去padding，再用Pillow LANCZOS得到有效1280×720／720×1280；不靠黑色像素猜边框，不做颜色匹配。
- VBench保留原生画布，不能使用GT指标去padding、统一720p后的媒体。原生时间轴已正确时直接评分；需要投影时采用RGB无损编码并核对解码像素。

## 3. 固定数值参数与汇总

| 项目 | 本项目正式口径 |
|---|---|
| SSIM | scikit-image 0.26.0；RGB [0,1]；data_range=1；高斯11×11、sigma=1.5；channel_axis=-1；population covariance |
| PSNR | RGB [0,1]；float64逐帧MSE后求dB，不先平均全视频MSE |
| LPIPS | lpips 0.1.4，AlexNet v0.1，FP32，eval／inference_mode；输入[-1,1]；无AMP／TF32，不额外缩至256或分块 |
| VBench | 官方commit `fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490`；custom_input；固定本地权重；Imaging Quality预处理longer |
| 尺度 | 成像质量raw值除100一次，其他五项沿用原尺度；展示时六项统一×100 |
| 汇总 | 每视频先逐帧平均，再视频等权；同时给实际n、预期n及参与ID |

PSNR零MSE保存为`null`并附`psnr_infinite=true`，代表正无穷，不是缺失，不封顶；非法NaN不属于此例外。JSON落盘前将NumPy float／bool转为Python原生类型。

**Temporal Flickering全量计算，不做静态筛选。** 旧实验中已存在的RAFT／静态共同子集属于历史记录，不进入当前主表，也不是验收门槛；不要为整理或新一轮评分自动启动它们。

模型比较核对相同ID交集，不只比较相同n。A849 dev40步、蒸馏基座8步、消融step232／600均需实名标注；推理协议或训练步数不同，不能把全部差异归因于训练数据。V4部分TripVVT经过看输出选样，应披露选择偏差。

## 4. 并行、依赖与失败处理

- 纯CPU准备、SSIM／PSNR、汇总和打包在login执行，不为CPU排GPU。历史205167中的CPU并行是用户单次明确授权的例外，不是默认规则。
- GPU仅使用testqueue；检查已有分配、真实空闲GPU及剩余时间，再使用锁或独占step。是否释放整个allocation以本任务授权为准。
- 用进程处理多个视频、少量线程处理帧；限制OMP／MKL／OpenBLAS和解码线程，避免进程数×帧线程×数值库线程过量叠加。多个模型可复用同一GT解码。
- LPIPS与VBench使用各自已验证环境，必要时独立子进程隔离；不能假定VBench环境也安装了lpips。固定版本与权重，不升级共享环境来碰运气。
- LPIPS默认batch4，OOM只降至2／1，不改变分辨率、精度或协议。VBench分批运行，核对每个预期视频是否返回分数，不能只接受官方批次均值。
- 先覆盖横竖屏、短／长片和不同参考类型的小测，再扩大。失败记录样本、维度和原因；部分成功值保留，不填0，不按效果换样本或seed。
- 续跑只复用身份一致的complete记录。历史failure文件、旧PID、日志短时不变或已有ZIP，不能单独证明当前任务失败／完成。

`metric_examples/`提供CPU测试与GPU小测命令；正式实验通过不等于通用示例已完成独立GPU验收。本次整理不运行GPU或重新评分。

## 5. 实测速度与预算

计数单位是“一个模型输出视频”，不是任务数、指标标量数或单帧。下列均为历史特定条件的观测，含4–10秒混合长度，不是另一台机器或纯10秒数据的保证。

| 阶段 | 条件与计时范围 | 实测／历史参考 |
|---|---|---:|
| SSIM＋PSNR | 历史4 CPU工作线程，两项联合核 | 约250输出/小时 |
| SSIM＋PSNR | 历史16 CPU可用、12工作线程 | 约400输出/小时 |
| LPIPS | 单H200、16 CPU、128GB；FP32、batch4；1200输出／1时14分08秒 | 约970输出/小时 |
| VBench五项GPU质量 | 4×H200、56 CPU、384GB；批64；1200输出；质量阶段7802.7秒 | 553.7输出/小时 |
| VBench原始闪烁CPU | 历史单worker；1200输出，近似2433.8秒 | 约1775输出/小时 |
| 消融九指标端到端 | 4×H200；节点CPU 8进程×4线程，login 2×2，闪烁2进程；600输出；评分＋汇总验收2487.0秒 | 868.5输出/小时 |

消融九指标端到端约41.5分钟，含前置检查约48.8分钟。它不是五项VBench的独立吞吐，也不是单卡速度。历史四模型VBench阶段中部分GPU还运行过后续RAFT，不能称为单独关闭静态筛选后的性能复测。

小测预算为`小测墙钟×全量输出数÷小测输出数`，混合尺寸／帧数应分组估算。保留首条、模型加载与冷启动；并行阶段墙钟不相加，累计GPU子进程秒数也不是端到端耗时。未实测的单卡吞吐或四卡外推必须标为估计。

速度证据：[四模型VBench](frozen300_vbench_20261115/metadata/speed_audit.json)、[消融用时](frozen300_data_ablation_20261115/report/timing_report.md)、[消融原始计时](frozen300_data_ablation_20261115/metadata/timing.json)。历史三指标参考见[通用指南](SSIM_PSNR_LPIPS_README.md)。运行证据保留本地，GitHub不包含全部数据文件。

## 6. 完成与清理

验收检查完整期望键、实际解码帧数、时间／画幅、有限数值及PSNR标记，从逐项数据独立复算视频和模型均值。自动技术通过不代表人工编辑效果通过。最终300集、116集和VLM校准／非校准分表分别保留。

清理前分清“浏览副本”与“送评证据”：VLM实际卡片／参考帧、请求签名及响应，VBench评分投影、冻结媒体和逐视频分数都需保留。只清理有成功上传回执的ZIP、确认无正式引用的可重建副本，保留清单和恢复入口；不追加远端哈希、大小核对或整包回读。

源码、固定Prompt、依赖、说明和配置纳入Git；模型、环境、媒体、缓存、运行清单、分数、日志、ZIP和凭据留本地。归档保留来源与结论，不恢复退役Lance/GOKU执行入口。
