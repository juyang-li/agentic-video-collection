# OmniEdit-Bench

This repository contains a comprehensive benchmark for instruction-based video editing. It evaluates whether a model can edit an input video according to a natural-language instruction while preserving unrelated content and maintaining visual, temporal, and audio consistency.

The benchmark covers five tracks: spatial track, temporal track, reasoning track, audio track, and reference-based track. Each task provides a source video and an editing instruction. Reference-based tasks additionally provide a reference image or reference video.

The default evaluator is [`gemini_eval.py`](gemini_eval.py), which uses Gemini as a multimodal judge to score edited videos.

## Benchmark Overview

![Tracks overview](assets/tracks_overview.png)

The benchmark contains 790 tasks across five tracks:

| Track | Metadata file | # Tasks | Main evaluation focus |
|---|---:|---:|---|
| Spatial | `spatial_benchmark.json` | 240 | Object-level, attribute-level, and global visual edits |
| Temporal | `temporal_benchmark.json` | 200 | Action semantics, motion attributes, camera control, and temporal composition |
| Reasoning | `reasoning_benchmark.json` | 50 | Spatial, temporal, causal, physical, and hypothetical reasoning edits |
| Audio | `audio_benchmark.json` | 100 | Environmental sound, speech, and object sound editing |
| Reference | `reference_benchmark.json` | 200 | Video editing guided by an additional reference image or video |

Most videos are provided at 720p resolution, including both landscape `1280x720` and portrait `720x1280` formats. Most fine-grained categories contain 10 tasks.

## Task Format

Each `*_benchmark.json` file is a list of task entries.

For non-reference tracks:

```json
{
  "video_id": "Sp_Object_direction_change_01",
  "source_video": "Spatial/Subject-Level/Object_direction_change/1_1280x720.mp4",
  "editing_instruction": "Rotate the monkey in the video to face left instead of right."
}
```

For the Reference track, each task additionally contains a `reference` field:

```json
{
  "video_id": "Ref_Reference_motion_amplitude_change_01",
  "source_video": "Reference/Reference_Action_Attribute_Editing/Reference_motion_amplitude_change/1_720x1280.mp4",
  "editing_instruction": "Make the amplitude of the woman's leg lift same as the amplitude shown in the reference video.",
  "reference": "Reference/Reference_Action_Attribute_Editing/Reference_motion_amplitude_change/Reference/1_1280x720.mp4"
}
```

Field definitions:

| Field | Required | Description |
|---|---|---|
| `video_id` | Yes | Unique task identifier. It is also the expected filename stem for the model output. |
| `source_video` | Yes | Relative path to the original video under the benchmark root. |
| `editing_instruction` | Yes | Natural-language instruction describing the required edit. |
| `reference` | Reference track only | Relative path to the reference image or reference video. |

## Track Taxonomy

### Spatial Track

The Spatial track evaluates whether a model can correctly modify visual content while preserving unrelated objects and regions.

Fine-grained categories:

- Subject-Level: `Object_direction_change`, `Object_location_swap`, `Object_style_change`, `Object_location_change`, `Object_replacement`, `Object_removal`, `Object_adding`, `Object_number_change`, `Object_visual_effects_adding`, `Object_State_change`
- Attribute-Level: `Texture_change`, `Color_change`, `Material_change`, `Size_shape_change`, `Appearance_change`, `Clothes_change`
- Global-Level: `Landscape_change`, `Global_visual_effects_adding`, `Relighting`, `Environment_change`, `Time_change`, `Season_change`, `Global_style_change`, `Weather_change`

### Temporal Track

The Temporal track evaluates editing over time, including action changes, motion control, camera dynamics, and temporal structure.

Fine-grained categories:

- Motion Semantic: `Action_category_change`, `Action_content_change`, `Facial_expression_change`
- Camera Attribute: `Camera_focal_length_change`, `Camera_trajectory_change`, `Camera_viewpoint_transformation`, `Camera_speed_change`, `Camera_shot_scale_change`
- Motion Attribute: `Motion_frequency_change`, `Motion_trajectory_change`, `Motion_direction_change`, `Motion_speed_change`, `Motion_amplitude_modulation`
- Temporal Composition: `Multi-stage_state_transition`, `Temporal_synchronization`, `Temporal_reordering`, `Gradual_state_change`, `Temporal_delay`, `Motion_deletion`, `Motion_insertion`

### Reasoning Track

The Reasoning track evaluates whether a model can infer the intended edited result when the instruction requires implicit reasoning rather than direct object replacement.

Fine-grained categories:

- `Spatial_reasoning_editing`
- `Hypothetical_reasoning_editing`
- `Temporal_reasoning_editing`
- `Physical_Attribute_change`
- `Causal_reasoning_editing`

### Audio Track

The Audio track evaluates sound addition, replacement, removal, preservation, and audio-visual synchronization.

Fine-grained categories:

- Environmental audio editing: `Environmental_sound_adding`, `Environmental_sound_change`, `Environmental_sound_removal`
- Human speech editing: `Speech_content_change`, `Speech_emotion_change`, `Speech_speed_change`, `Speech_tone_change`
- Object sound editing: `Object_sound_change`, `Object_sound_insertion`, `Object_sound_removal`

### Reference Track

The Reference track evaluates whether a model can follow both the text instruction and an additional reference image or video. High accuracy requires both instruction compliance and reference alignment.

Fine-grained categories:

- Action Attribute Editing: `Reference_motion_amplitude_change`, `Reference_motion_frequency_change`, `Reference_motion_speed_change`
- Temporal Composition Editing: `Reference_motion_insertion`
- Attribute Level: `Reference_clothes_change`, `Reference_size_shape_change`, `Reference_color_change`, `Reference_appearance_change`, `Reference_texture_change`
- Subject Level: `Reference_object_style_change`, `Reference_object_adding`, `Reference_object_replacement`
- Camera Editing: `Reference_camera_trajectory_change`
- Action Semantic Editing: `Reference_facial_expression_change`, `Reference_action_change`
- Global Level: `Reference_visual_effects_adding`, `Reference_weather_change`, `Reference_global_style_change`, `Reference_background_change`, `Reference_season_change`

## Preparing Model Outputs

Put edited videos under `eval_720p_10s/<model_name>/`.

Each edited video must be named with the corresponding `video_id`:

```text
eval_720p_10s/
└── your_model_name/
    ├── Sp_Object_direction_change_01.mp4
    ├── Te_Action_category_change_01.mp4
    ├── Re_Spatial_reasoning_editing_01.mp4
    ├── Au_Environmental_sound_adding_01.mp4
    └── Ref_Reference_motion_amplitude_change_01.mp4
```

The evaluator searches for each edited video at:

```text
eval_720p_10s/<model_name>/<video_id>.mp4
```

If an output video is missing, `gemini_eval.py` skips that task.

## Gemini Evaluation

![Evaluation pipeline](assets/evaluation_pipeline.png)

[`gemini_eval.py`](gemini_eval.py) sends the following inputs to Gemini:

- the source video;
- the model-generated edited video;
- the user editing instruction;
- the reference image or video for Reference-track tasks.

The judge prompt is defined in [`eval_configs/prompts.json`](eval_configs/prompts.json). Gemini is required to return only the following JSON object:

```json
{
  "accuracy": 0,
  "preservation": 0,
  "realism": 0,
  "consistency": 0,
  "reason": "Brief explanation focused on errors."
}
```

All four dimension scores use a 0-5 scale:

| Score | Meaning |
|---:|---|
| 0 | Completely wrong |
| 1 | Major failure |
| 2 | Partially correct but flawed |
| 3 | Acceptable |
| 4 | Good |
| 5 | Nearly perfect |

### Evaluation Dimensions

- `accuracy`: whether the editing instruction is correctly followed. This is the most important metric.
- `preservation`: whether unrelated objects, regions, actions, and sounds remain unchanged.
- `realism`: whether the edited video is physically and perceptually plausible.
- `consistency`: whether spatial structure, temporal dynamics, identity, and audio-visual synchronization remain stable.

For Reference-track tasks, `accuracy` also requires alignment with the provided reference image or video.

### Overall Score

`gemini_eval.py` computes an `overall_score` from Gemini's four dimension scores:

```python
penalty = accuracy * 0.2 if accuracy <= 5 else 1.0
overall_score = (
    0.50 * accuracy
    + 0.20 * preservation * penalty
    + 0.15 * realism * penalty
    + 0.15 * consistency * penalty
)
```

This formula makes instruction following dominant. When `accuracy` is low, the contributions of `preservation`, `realism`, and `consistency` are also down-weighted, preventing visually pleasing but incorrect edits from receiving high final scores.

## Running Evaluation

### 1. Install Dependencies

```bash
pip install requests numpy
```

### 2. Configure `gemini_eval.py`

Edit the following variables near the top of [`gemini_eval.py`](gemini_eval.py):

```python
GEMINI_API_KEY = "YOUR_OFFICIAL_GEMINI_API_KEY"
BENCHMARK_BASE = "YOUR_BENCHMARK_ROOT_DIRECTORY"
MODELS = ["YOUR_EVALUATED_MODELS"]
```

Example:

```python
GEMINI_API_KEY = "your_api_key"
BENCHMARK_BASE = "/path/to/Video Editing Benchmark"
MODELS = ["my_video_editing_model"]
```

By default, model outputs are read from:

```python
MODELS_DIR = os.path.join(BENCHMARK_BASE, "eval_720p_10s")
```

and evaluation results are saved to:

```python
RESULT_SAVE_DIR = os.path.join(BENCHMARK_BASE, "evaluation_results")
```

### 3. Run the Evaluator

```bash
python gemini_eval.py
```

The script evaluates all configured models on all available tracks:

```python
TRACK_FILES = {
    "spatial": "spatial_benchmark.json",
    "temporal": "temporal_benchmark.json",
    "reasoning": "reasoning_benchmark.json",
    "audio": "audio_benchmark.json",
    "reference": "reference_benchmark.json",
}
```

The current script uses 2 multiprocessing workers by default and retries failed API calls for up to 3 rounds. If API rate limits occur, reduce `num_worker` in `gemini_eval.py` and rerun the script.

## Evaluation Outputs

Per-task detailed results are saved as:

```text
evaluation_results/<track>_<model_name>_details.json
```

Example:

```text
evaluation_results/spatial_my_video_editing_model_details.json
```

Each record contains:

- `accuracy`
- `preservation`
- `realism`
- `consistency`
- `reason`
- `overall_score`
- `video_id`
- `editing_instruction`

Track-level summaries are saved as:

```text
evaluation_results/<track>_full_summary.json
```

Example:

```json
{
  "my_video_editing_model": {
    "Avg_Overall": 3.4215,
    "Count": 240
  }
}
```

`Count` is the number of successfully evaluated tasks. It may be lower than the total number of tasks if model outputs are missing or API calls fail.

## Reproducibility Notes

- `gemini_eval.py` uses `temperature = 0.0` for more stable automatic judgments.
- If a `video_id` already appears in the corresponding details file, the script skips that task. This enables checkpoint-style evaluation resumption.
- Missing model outputs are skipped and are not automatically counted as zero-score failures.
- Reference-track evaluation submits the source video, edited video, and reference asset. The reference asset may be either an image or a video.
- For fair comparison, use the same source videos, editing instructions, output naming convention, Gemini API endpoint, and `eval_configs/prompts.json`.

## Recommended Reporting

When reporting benchmark results, include:

- `Avg_Overall` for each track;
- the number of successfully evaluated tasks, `Count`, for each track;
- optional per-dimension averages for `accuracy`, `preservation`, `realism`, and `consistency`;
- the Gemini model/API endpoint used by `gemini_eval.py`;
- how missing output videos were handled.
