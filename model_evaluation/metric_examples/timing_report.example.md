# 用时报告样式

这是字段与计时口径示意，所有“待填”均不是实测。示例CLI会自动生成实际的`timing.json`和`timing_report.md`。

## 本次条件

| 字段 | 填写内容 |
|---|---|
| 样本 | 预期／完整成功／部分成功／失败输出数，模型及数据集 |
| 硬件与并行 | CPU、工作进程／线程、GPU型号与数量、LPIPS batch |
| 软件与缓存 | 依赖版本、VBench commit、权重、cold／warm／unknown |
| 媒体协议 | 片段区间、fps、端点、帧数、原生画布；GT指标另列去padding与有效尺寸 |
| 实际指标 | SSIM＋PSNR联合核、LPIPS或具体VBench维度，不把子集称全量 |

## 实际用时

| 范围 | 秒数 | 包含的工作 |
|---|---:|---|
| 全程墙钟 | 待填 | 启动、预检、准备、加载、评分及结果写盘，保留首条和冷启动 |
| GT联合CPU阶段 | 待填 | 解码／对齐／哈希、SSIM＋PSNR；不能称某一项独立耗时 |
| LPIPS阶段 | 待填 | 说明是否包括加载、传输、解码及写盘；GPU边界同步 |
| VBench各维度API | 待填 | 官方API包含的加载、解码与计算，不能虚构为纯前向 |

输出/小时＝完整成功输出数×3600÷全程墙钟秒数。帧对/秒＝完整成功视频的目标帧数之和÷全程墙钟秒数。一个输出不是一个指标标量；CPU／GPU重叠时用整段墙钟，不能将并行阶段相加。

## 失败与估计

列出失败ID／模型／维度及原因，不填0。仅对同规格且无失败的小测给出线性估计，注明固定开销、缓存及I/O差异；异质数据分组估算，不将单卡线性外推写成四卡实测。
